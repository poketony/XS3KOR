명령 실행 기준: XS3KOR/tools/x30. 일상 작업 순서는 ../README.txt를 참고하세요.
검증 개수와 초기 번역 상태는 구현 당시의 기록이며 현재 결과와 다를 수 있습니다.

과거 에피소드 요약 MES 수동 빌드 (2026-10-24)

작업과 실행
- 작업 폴더: 0.X30/mnu/pse/kr. 같은 폴더의 Build_PSE.bat를 더블클릭하면 등록된 6개를 검사/변환합니다.
- AC.mes.kor.txt는 기존 사용자 번역을 그대로 직접 읽습니다. 수정하거나 사본으로 교체하지 않았습니다.
- EP1.mes.txt, EP2.mes.txt, opening.mes.txt, PP.mes.txt, test.mes.txt는 일본어 원문 UTF-8 추출본입니다.
- 기존 .mes 바이너리 6개는 보존하며 입력 TXT가 없다고 대신 사용하지 않습니다.
- TXT 하나를 Build_PSE.bat에 드롭하면 이름으로 자산을 선택해 그 파일만 변환합니다.
- 이름이 다른 TXT는 --asset으로 형식을 지정합니다. 저장소 밖이나 codex-lab의 파일은 입력으로 받지 않습니다.
- CLI: 0.X30\mnu\pse\kr\Build_PSE.bat "0.X30\mnu\pse\kr\EP1.mes.txt" --check
- 다른 이름: Build_PSE.bat --asset EP1 "경로\번역.txt"
- Python: python -B tools/x30/build_pse.py --asset AC --check
- --asset 선택: AC, EP1, EP2, opening, PP, test. --check는 저장하지 않습니다.
- XS3_NO_PAUSE=1이면 BAT의 종료 대기를 생략합니다. 상대 경로는 호출한 폴더 기준입니다.

출력과 독립성
- 결과는 작업 폴더의 *.mes.new입니다. 기존 TXT/MES와 외부 ROM은 수정하지 않습니다.
- 도구 코드는 tools/x30에 있고 원본 MES/작업 TXT/치환표는 0.X30/mnu/pse/kr에서 직접 읽습니다. tools/x30/edit 번역 사본이나 codex-lab 의존성은 없습니다.
- ROM 적용은 .new를 제거한 이름으로 외부 Xenosaga3/X30_UNPACKED/mnu/pse/jp에 사용자가 수동 반영합니다.
- X31/X32 및 본편 컷신의 기존 번역/인코딩 파이프라인은 수정하지 않았습니다.
- Extract_PSE.batlock을 사용할 때만 .bat로 바꾸면 일본어 원문을 추출합니다. --asset EP1로 하나만 선택하거나 --check로 저장 없이 검사할 수 있습니다. 기존 TXT가 하나라도 있으면 전체 저장을 중단합니다. 사용 후 .batlock으로 돌립니다.

TXT 규칙
- 원래 #MESSAGE 0, #MESSAGE 1, ... 줄을 유지하고 그 아래 본문을 번역합니다.
- 숫자/순서/개수를 변경하지 마세요. 게임은 헤더의 숫자로 재배열하지 않고 등장 순서대로 저장합니다.
- 본문의 빈 줄, 공백, 문장 부호, $rubyb; 등의 표기는 그대로 취급합니다. [n]/[menu_sita]는 특수 치환 지시자가 아닙니다.
- UTF-8 BOM은 허용합니다. 작업 TXT는 LF 또는 CRLF를 쓸 수 있고, 게임용 결과는 CRLF로 저장합니다.
- 마지막 본문 줄도 개행으로 끝나야 합니다. 그렇지 않으면 게임 파서가 마지막 줄을 버리므로 빌드를 중단합니다.
- 본문의 #는 메시지 종료, ASCII FRAME은 시간 명령으로 인식되므로 삽입을 허용하지 않습니다.
- NUL, 인코딩 불가 문자, 잘못된 헤더/ID는 오류입니다. 오류 문자를 버리거나 임의로 문장 부호를 바꾸지 않습니다.
- 한글 -> XENOSAGA KOR-JPN.json -> EUC-JIS-2004로 저장합니다.
- 변경한 결과에는 마지막 메시지 스캔을 끝내는 NUL 1바이트를 명시적으로 붙입니다. 변경하지 않은 원문은 바이트 그대로 반환합니다.

실행 코드 근거와 용량
- SLPS 0024a4a8이 스크립트와 MES를 읽고, 00249980이 #MESSAGE별로 0x7ec(2,028)바이트 버퍼를 할당합니다.
- 00249748은 CRLF를 찾습니다. 00249790은 각 본문 줄에 제어 4바이트를 추가하고 문자열을 이어 붙입니다.
- 따라서 메시지마다 합계(치환/인코딩된 각 줄의 바이트 수 + 줄마다 4바이트) + 종결 NUL 1바이트가 2,028 이하이어야 합니다.
- 전체 파일은 0024a4a8의 0x19000(102,400)바이트 입력 버퍼를 넘을 수 없습니다.
- 문장 폭은 별도입니다. 버퍼에 들어간다고 화면에 한 줄로 들어간다는 뜻은 아닙니다. 실제 표시/음성 타이밍 검증은 필요합니다.

범위 구분
- EP1/EP2는 실행 코드의 과거 이야기 재생 경로에서 참조됩니다.
- AC는 이미 작업 중인 번역이 있으므로 수동 빌드에 포함했습니다. 이번 조사에서 정상 메뉴의 AC 호출은 확인하지 못했습니다.
- opening은 기존 자산, PP/test는 테스트용 문구를 포함합니다. 동일 포맷을 직접 리빌드할 수 있도록 포함했으며 모두 실제 플레이에 등장한다고 주장하지 않습니다.
- 에셋 6개에 MESSAGE 106개입니다. 새 자동 번역은 하지 않았습니다.
