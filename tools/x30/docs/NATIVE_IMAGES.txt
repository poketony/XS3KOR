명령 실행 기준: XS3KOR/tools/x30. 일상 작업 순서는 ../README.txt를 참고하세요.
검증 개수와 초기 번역 상태는 구현 당시의 기록이며 현재 결과와 다를 수 있습니다.

기존 PNG/JPG 작업본 수동 출력

입력과 실행
- 0.X30/mnu/kr/title1.png 옆의 Build_title1.bat: 타이틀 로고 이미지.
- 0.X30/mnu/intm/10.jpg 옆의 Build_10.bat: 인터미션 이미지.
- 0.X30/mnu/kr/wall.jpg 옆의 Build_wall.bat: 메뉴 배경의 일본어 타이틀 로고. 최초 추출 원본 상태입니다.
- 0.X30/mnu/syno/Build_synopsis_images.bat: 같은 폴더의 줄거리 JPG 71개. 이미지 하단의 일본어 로고를 편집할 수 있도록 원본 상태로 추출했습니다.
- 0.X30/jpg/kr/Build_database_images.bat: 같은 폴더의 데이터베이스 JPG 25개. 세그먼트 화면(0393), 낚시 간판(0400), 튜토리얼 화면(0431~0453)입니다. 아직 일본어 원본 상태이며 이미지 편집/번역은 별도 작업입니다.
- 더블클릭하면 해당 작업본을 직접 읽습니다. 다른 이미지를 BAT에 드롭하면 그 파일을 읽습니다.
- CLI 예: 0.X30\mnu\kr\Build_title1.bat "0.X30\mnu\kr\title1.png" --check
- 입력은 저장소의 0.X30 또는 tools/x30 안에 있어야 합니다. 상대 경로는 호출한 폴더 기준입니다.
- tools/x30/Build_native_images.bat는 위 작업본 99개를 한 번에 검사하고 124개 파일로 출력합니다.
- 직접 실행: python -B tools/x30/build_native_images.py --asset intm10 --check
- Python 3.10 이상과 Pillow가 필요합니다. XS3_NO_PAUSE=1이면 BAT 종료 대기를 생략합니다.
- 줄거리 BAT 기본 실행은 71개 전체, 010.jpg 같은 원래 이름의 JPG 하나를 드롭하면 해당 파일만 출력합니다.
  다른 이름으로 만든 이미지는 CLI의 --asset syno010으로 대상을 지정합니다. 예:
  python -B tools/x30/build_native_images.py --asset syno010 "0.X30/mnu/syno/custom.jpg" --check
  synopsis.txd 번역용 Build_synopsis.bat와는 별개입니다.
- 데이터베이스 BAT 기본 실행은 25개 전체, dtimg_0393.jpg 하나를 드롭하면 해당 이미지와 dtimg_1393.jpg 사본을 함께 출력합니다.
  +1000 사본은 원본 바이트가 같은 것으로 확인했습니다. 따로 편집 사본을 관리하지 않습니다.
  사용자 지정 이름은 --asset dtimg0393으로 지정합니다. --check는 저장 없이 검사합니다.
  DBC/DBC2 텍스트 번역용 Build_database.bat와는 별개입니다.

출력과 보존
- 각 작업 폴더에서 원본 파일명 뒤에 .new를 붙여 출력합니다. 예: title1.png.new, 10.jpg.new, wall.jpg.new.
- 줄거리 JPG도 같은 폴더의 010.jpg.new 같은 이름으로 출력합니다.
- 데이터베이스 JPG는 같은 작업 폴더에 원래 번호와 +1000 번호로 함께 출력합니다. 예: dtimg_0393.jpg.new와 dtimg_1393.jpg.new.
- 각 작업 폴더의 original 하위 폴더는 일본판 원본 보관용입니다. 편집하지 마세요. native_sources.json의 SHA-256으로 검사합니다.
- 같은 폴더의 Extract_*.batlock을 필요할 때만 .bat로 바꿔 원본을 편집 경로로 복사하고 다시 잠급니다. 이미 게임용 이미지이므로 추출도 재인코딩하지 않습니다.
- 기존 편집 이미지가 하나라도 있으면 추출 전체를 거부합니다. --check는 저장하지 않습니다. 추출을 위해 작업 이미지를 지우지 말고 필요한 파일을 먼저 따로 백업하세요.
- 이미 게임용 PNG/JPG이므로 재압축, 색상 변경, 알파 변환, 메타데이터 삭제를 하지 않습니다.
- 검사 통과 시 입력 바이트 그대로 출력합니다. 작업 이미지와 외부 ROM 폴더는 수정하지 않습니다.
- 선택한 파일 모두 검사한 뒤 출력하므로 잘못된 입력 하나 때문에 나머지를 먼저 저장하지 않습니다.
- 실패 시 기존 output이 남아 있을 수 있습니다. BUILD SUCCEEDED와 종료 코드 0을 확인하세요.
- 결과는 사용자가 외부 Xenosaga3/X30_UNPACKED의 같은 경로에 수동 적용합니다.
  외부 ROM BAT는 그 폴더만 읽으며 이 저장소를 자동 참조하지 않습니다.

게임 형식 검사
- 데이터베이스 JPG는 211x134, 나머지는 512x448 고정입니다.
- title1: 8비트 RGBA, 비인터레이스, 단일 이미지 PNG. 최대 1,048,576바이트.
- intm10: 8비트 RGB, SOF0 베이스라인, 단일 Y/Cb/Cr 스캔 JPEG. 최대 262,144바이트.
  표준 4:4:4 / 4:2:2 / 4:2:0 샘플링을 허용합니다. 프로그레시브, CMYK, 회색조 등은 거부합니다.
- wall: 같은 JPEG 형식이나 최대 크기는 229,376바이트로 더 작습니다.
- syno010 등 줄거리 JPG: 같은 JPEG 형식, 최대 130,560바이트입니다.
- dtimg0393 등 데이터베이스 JPG: 같은 JPEG 형식, 최대 30,720바이트입니다.
- 읽기 버퍼 근거: SLPS 00A81818의 PNG 입력/작업 공간 간격은 0x100000;
  001B3AC0은 0x140000 할당 중 +0x100000부터 JPG를 읽습니다.
- wall: SLPS 002DE938이 ID 0x0900000C, 512x448, 출력 0xE0000바이트를 설정합니다.
  002CD8C8은 너비*높이(0x38000)만큼 압축 파일 입력 버퍼를 할당하고 같은 JPG 디코더를 호출합니다.
- 줄거리: SLPS 001B4328은 mnu/syno/NNN.jpg를 버퍼 시작에 읽고 +0x1FE00부터 디코딩합니다.
  입력이 그 간격을 넘으면 디코딩 중 읽는 압축 데이터를 덮어쓸 수 있으므로 저장 전에 거부합니다.
- JPG 0018DF68은 SOF0을 처리하고, 0018D1B0/0018DA30은 위 세 샘플링과 3성분 스캔을 처리합니다.
  PNG 00192F00/00192D20에서 청크와 연속 IDAT 처리를 확인했습니다.
- 데이터베이스: SLPS 002DE7A8이 jpg/dtimg_NNNN.jpg 이름을 만들고 002C73E0이 파일을 읽습니다.
  002C71B0은 004012D0/D4의 상수 212x144를 곱하고 2048바이트 경계로 올려 압축 입력 0x7800바이트를 할당합니다.
  002C7370 콜백이 같은 JPEG 디코더를 호출합니다. 편집 이미지 크기는 실제 원본의 211x134를 유지합니다.
- 이 검사는 파일 형식/버퍼 범위와 무변환 출력을 검증합니다. 게임 화면 품질 확인을 대신하지 않습니다.

통합 빌드
- 예전에 ROM 폴더에서 가져온 preserved 이미지 사본은 보존 기록으로 남기되 빌드 입력에서는 제외했습니다.
- 연결 시점의 저장소 작업본은 그 사본과 실제 그림/파일 바이트가 달랐습니다.
  따라서 이후 통합 결과가 예전 릴리스와 다른 것은 의도된 입력 경로 변경입니다.
- 기존 컷신은 바이트 그대로 보존합니다. 폰트는 FONTS.txt의 작업 시트를 직접 리빌드하되 기존 픽셀과 마지막 3,072바이트를 유지했습니다.
- wall.jpg와 줄거리 JPG 71개는 원본 아카이브에서 바이트 그대로 추출했으므로 편집 전에는 아카이브 내용이 달라지지 않습니다.
- 데이터베이스 JPG 25쌍도 원본과 바이트가 같으며, 편집 전에는 아카이브 내용이 달라지지 않습니다. 다른 인물/장면 삽화와 mcimg 컷신 미리보기는 추가 생성 대상이 아닙니다.
- 새 릴리스의 모든 항목/비편집 구간은 현재 작업 입력에 맞춰 검증합니다.
