명령 실행 기준: XS3KOR/tools/x30. 일상 작업 순서는 ../README.txt를 참고하세요.
검증 개수와 초기 번역 상태는 구현 당시의 기록이며 현재 결과와 다를 수 있습니다.

전투 UI 이미지 문구 편집

작업 입력: 0.X30/mnu/kr/window의 PNG 10개
실행: 같은 폴더의 Build_window.bat
원본: 같은 폴더의 window0.xtx, window1.xtx, window2.xtx
결과: 같은 폴더의 window0.xtx.new, window1.xtx.new, window2.xtx.new
추출: Extract_window.batlock을 필요할 때만 .bat로 바꿔 사용하고 다시 잠급니다.
세 원본에서 공통 PNG 10장이 같은지와 무수정 재삽입을 검사합니다. 기존 PNG가 하나라도 있으면 전체 저장을 거부합니다. --check는 저장하지 않습니다.

더블클릭하면 작업 PNG 10개를 읽어 결과 세 개를 만듭니다. 이름을 유지한 PNG를
하나 또는 여러 개 드롭하면 해당 문구만 드롭한 파일로 대체하고 나머지는 작업
폴더의 PNG를 읽습니다. 드롭 입력은 저장소의 0.X30 또는 tools/x30 안에 둡니다.
없는 파일, 다른 이름, 중복 입력, 크기 오류는 기본 이미지로 대체하지 않고 실패합니다.
CLI 예: 0.X30\mnu\kr\window\Build_window.bat "0.X30\mnu\kr\window\command.png" --check
--check는 저장하지 않습니다. 상대 경로는 실행한 폴더 기준입니다.
XS3_NO_PAUSE=1이면 BAT의 마지막 키 입력 대기를 생략합니다.

파일명과 크기 (가로 x 세로, 픽셀)
- enemy_info.png: 87 x 17, ENEMY INFO
- boost.png: 67 x 17, BOOST
- command.png: 101 x 17, COMMAND
- boost_red.png: 61 x 17, 붉은 BOOST
- stock.png: 67 x 17, STOCK
- player.png: 92 x 10, PLAYER
- enemy.png: 92 x 10, ENEMY
- anima.png: 67 x 15, ANIMA와 그 배경 테두리
- act_large.png: 59 x 15, 큰 ACT와 화살표 배경
- act_small.png: 44 x 15, 작은 ACT와 화살표 배경

최초 배치는 영문 원본 그대로이며 자동으로 번역하지 않았습니다. 크기와 투명도를
유지한 정지 PNG만 받습니다. ANIMA/ACT 이미지에는 배경도 있으므로 글자 이외의
부분을 유지하려면 편집기에서 해당 부분을 건드리지 마세요.

팔레트는 다른 UI와 공유하므로 변경하지 않습니다. 추가한 색은 해당 원본 팔레트에서
가장 가까운 RGBA로 변환되며 quantized 수로 보고합니다. 특히 PLAYER/ENEMY는
원래의 어두운 색상 범위가 좁습니다. 결과 색상과 작은 글자의 가독성은 게임에서
확인해야 합니다. 글자가 긴 경우 이미지 크기를 늘리지 말고 문구나 디자인을 조정하세요.
원래 색/투명도의 픽셀은 중복 팔레트 인덱스까지 보존하므로 원본 PNG의 무수정
리빌드는 세 XTX 원본과 바이트 단위로 같습니다.

window0/1/2는 스토리 진행에 따라 교체됩니다. 문구는 모두 같지만 초상화 일부가
다르므로 결과 하나를 세 이름으로 복사하면 안 됩니다. 도구가 각 버전의 원본을
별도로 읽고 문구 인덱스 10,901바이트 범위만 편집합니다. 헤더, 파일 크기,
팔레트, 초상화, 숫자/영문 글리프, 버튼과 다른 장식은 원본별로 보존합니다.

형식 근거
- SLPS 001b85a0: 진행 상태에 따른 window0/1/2 로드.
- 00199628/0023a660: CT32 업로드 384x128, DBW8; PSMT8 텍스처, TBW16.
- 00402270 포인터 표의 table0=004016b8, 다음 표=00401fa0.
- 002ce7b8/002ceff0: 20바이트 레코드의 x/y/w/h/상대 CBP를 사용.
- 편집 대상 스프라이트 ID: 18~22, 27, 28, 32, 42, 101.
- 나머지 103개 스프라이트의 픽셀 및 전체 113개 스프라이트의 팔레트와 편집
  바이트가 겹치지 않음을 별도로 확인했습니다. 운영 도구는 이 분석 자료를 읽지 않습니다.

Python 3.10 이상과 Pillow만 필요합니다. NumPy, SLPS/OVL, codex-lab, 외부 ROM
폴더는 실행 의존성이 아닙니다. 원본 SHA-256이 다르면 중단합니다.
결과는 저장소 안에만 생성하며 외부 ROM 작업 폴더로 자동 동기화하지 않습니다.
원본/작업 PNG를 덮어쓰지 않습니다. 실패한 실행의 output은 적용하지 마세요.
