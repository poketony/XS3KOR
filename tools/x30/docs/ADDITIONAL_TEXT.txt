명령 실행 기준: XS3KOR/tools/x30. 일상 작업 순서는 ../README.txt를 참고하세요.
검증 개수와 초기 번역 상태는 구현 당시의 기록이며 현재 결과와 다를 수 있습니다.

전투 표시 문자열과 미니게임 텍스트 (2026-10-24)

대상은 njBtlText.bin, mg1/jp/Message.Dat, mg1/com/Stage/World.Dat입니다.
컷신/자막 파일이나 그 기존 파이프라인은 포함하지 않습니다.

njBtlText.bin
- 0.X30/mnu/kr/njBtlText.KOR.txt -> 같은 폴더의 Build_njBtlText.bat -> njBtlText.JPN.bin.new
- 복구 TXT 자체를 위 작업 경로로 이동했습니다. tools/x30/edit에는 사본을 두지 않습니다.
- 한 파일만 검사: python -B build_menu.py --asset njBtlText --check
- 51개 표시 문자열. 원래 프로젝트에 TXT 없이 바이너리로만 있던 번역 8개를 치환표 역변환으로 복구했습니다.
- 복구한 문구: 스테이터스, 부스트, 공격, 상성, 무효, 약점, 강화, 흡수.
- 수정 전/후 문자열을 대조하여 바뀐 슬롯만 역변환했습니다. 원래의 일본어/영문을 무작정 한글로 치환하지 않습니다.
- 다시 한글 -> 대응 한자 -> EUC-JIS-2004로 변환한 바이트가 기존 바이너리와 일치함을 확인했습니다.
- 복구 당시 TXT의 빌드 결과는 원래 프로젝트 및 ROM 작업 폴더의 522바이트 파일과 완전히 같습니다.
- 기존 njBtlText.bin은 수정하지 않습니다. 같은 작업 폴더에 검증된 일본판 원본 njBtlText.JPN.bin을 추가했으며 이를 직접 읽습니다. 결과를 ROM에 수동 적용할 때 이름은 njBtlText.bin입니다.
- sources.json에 원본/보존 사본 해시와 복구한 번역 8개를 기록했습니다.

njBtlText의 저장 방식
- njDBcommon과 같은 상대 포인터 컨테이너 파서를 재사용합니다.
- 모든 번역이 원래 슬롯에 들어가면 포인터와 파일 크기를 유지하고 문자열 슬롯만 수정합니다.
  짧아진 문자열 뒤의 남은 공간은 NUL로 채워 기존 바이너리 편집 결과를 정확히 재현합니다.
- 슬롯을 넘는 문장이 있으면 검증된 njDBcommon 재구성 방식으로 문자열 풀/포인터/페이로드 크기를 갱신합니다.
- 현재 8개 번역은 모두 원래 슬롯 안에 들어갑니다. 길이 증가 경로는 회귀 테스트로 확인했으나 게임 검증은 필요합니다.

Message.Dat
- 0.X30/mg1/kr/Message.Dat.txt -> 같은 폴더의 Build_Message.Dat.bat -> Message.Dat.new
- 작업 TXT 자체를 이동했으며 tools/x30/edit에 중복 사본을 두지 않습니다. 원래 있던 Message.Dat 바이너리는 수정하지 않았습니다.
- BAT 더블클릭은 같은 폴더의 작업 TXT를 사용합니다. 다른 TXT를 드롭하거나 CLI 인자로 지정하면 그 파일을 직접 읽습니다.
- 드롭 입력은 저장소의 0.X30 또는 tools/x30 내부 TXT 하나이며, 없거나 형식이 틀리면 중단합니다. 기본 TXT로 대체하지 않습니다.
- CLI 예: 0.X30\mg1\kr\Build_Message.Dat.bat "0.X30\mg1\kr\Message.Dat.txt" --check
- 상대 경로는 명령 실행 폴더 기준입니다. XS3_NO_PAUSE=1 환경 변수로 BAT 종료 대기를 생략할 수 있습니다.
- 저장 없는 검사: python -B build_minigame.py --check
- 871개 문자열을 추출했습니다. 튜토리얼, 미니게임 문구와 캐릭터 이름/식별자 등이 들어 있습니다.
- 최초 추출 당시 프로젝트 BIN은 일본판 원본과 같았고 번역 TXT가 없었습니다. 새 작업 TXT는 그 원문을 그대로 옮긴 것입니다.
- 번역을 새로 수행한 것이 아닙니다. 현재 무수정 빌드 결과는 원본 31,483바이트와 같습니다.
- 같은 작업 폴더의 Message.Dat와 XENOSAGA KOR-JPN.json을 직접 읽습니다. minigame_sources.json의 해시로 검증하며 원본이 없으면 다른 사본으로 대체하지 않습니다.
- Extract_Message.Dat.batlock을 사용할 때만 .bat로 바꾸면 일본어 원문을 추출합니다. 기존 TXT는 덮어쓰지 않습니다. 사용 후 .batlock으로 돌립니다.

Message.Dat 구조와 한계
- 첫 2,048바이트: 리틀엔디안 16비트 참조 1,024개. 게임은 부호 있는 값으로 읽습니다.
- 그 뒤: EUC-JIS-2004 NUL 종결 문자열 풀. 포인터는 이 풀의 시작 기준 상대 주소입니다.
- 첫 871개 슬롯은 문자열을 순서대로 가리키고, 나머지 153개 슬롯 값은 0입니다.
  첫 슬롯도 0이므로 상대 주소 0은 유효한 첫 문자열입니다. 뒤의 0도 버리거나 새로운 문자열로 복제하지 않습니다.
  뒤 153개가 게임에서 실제로 사용되는지는 미확인입니다. 미사용 패딩/첫 문장 별칭 어느 경우에도 원래 0 값을 보존합니다.
- 모든 참조 1,024개와 문자열 풀 전체의 경계/NUL/디코딩을 검사합니다.
- 수정 시 문자열 풀을 원래 ID 순서로 다시 구성하고 참조를 갱신합니다. 동문 문자열이라도 서로 다른 ID는 합치지 않습니다.
- OV04.OVL의 00aa1ecc, 00aa25ac, 00a91510에서 LH(부호 확장)를 확인했습니다.
  각 문자열 시작의 상대 주소는 0~32767이어야 합니다. 32768 이상이면 저장 전에 중단합니다.
  마지막 문자열의 끝이 32768을 넘는 것과 시작 주소가 넘는 것은 다릅니다. 시작 주소를 검사합니다.
- 기존 도구의 풀 전체 65,536바이트 상한도 유지합니다. 이것을 실행 코드가 보장하는 메모리 용량으로 해석하지 마세요.
- ID 0099~0198은 스테이지 이름 영역이며 치환/인코딩 후 26바이트 이하로 제한합니다.
  OV04 00a91390은 32바이트 메뉴 행에 5바이트 접두사 "St 0."와 이름, NUL을 이어 붙입니다.
  SLPS 0030ce50/0030d250은 길이 제한 없는 strcat/strcpy 동작입니다. 길면 다음 행을 침범할 수 있습니다.
- 이보다 큰 풀 또는 다른 게임/다른 구조의 DAT는 지원한다고 가정하지 않습니다.

World.Dat

- 더블클릭/드롭/CLI/--check를 지원하며 다른 TXT를 지정하면 그 파일을 직접 읽습니다.
- CLI 예: 0.X30\mg1\kr\Build_World.Dat.bat "0.X30\mg1\kr\World.Dat.txt" --check
- Python: python -B build_minigame.py --asset World.Dat --check
- 원문 이름 10개를 추출했고 자동 번역은 하지 않았습니다. 같은 폴더의 World.Dat와 치환표를 직접 읽으며 world_sources.json의 해시로 검증합니다.
- Extract_World.Dat.batlock을 사용할 때만 .bat로 바꾸면 일본어 원문을 추출합니다. 기존 TXT는 덮어쓰지 않습니다. 사용 후 .batlock으로 돌립니다.
- OV04 00aa1c20에서 로드하고 00a90968/00a91390에서 파일 +0x38부터 32바이트 간격으로 이름을 표시합니다.
- ID 0000~0009, 이름마다 치환/인코딩 후 1~31바이트입니다. 끝의 NUL 1바이트를 남깁니다.
- 빈 이름은 게임의 월드 목록 루프를 중단시키므로 허용하지 않습니다.
- 파일 크기 1,656바이트, 헤더/스테이지 수/코드/설명 영역을 보존하고 변경한 이름 슬롯만 수정합니다.
- World.Dat의 설명 영역, Stage.Dat, Stage_*.BMP의 부가 데이터는 이번 도구의 편집 대상이 아닙니다.
  파일에 일본어가 있다는 이유만으로 실제 표시 여부를 단정하지 않습니다.

TXT의 공통 형식
//[0000]
내용
//[0001]
다음 내용

- njBtlText는 00~50, Message.Dat는 0000~0870의 ID를 사용합니다. 앞의 0 개수는 무관합니다.
- ID 뒤의 내용을 수정합니다. ID 누락/중복/알 수 없는 ID는 오류이며 순서 변경은 허용합니다.
- 다음 ID 직전의 개행 1개는 파일 형식 구분자입니다. 그 앞의 공백/추가 개행은 문자열 데이터로 보존합니다.
- 문장 부호, 꺾쇠, 제어코드와 \n은 임의로 변환하지 않습니다.
- 특히 Message.Dat의 $rubyb;/$rubys;/$rubye; 및 <R1>/<R2> 등은 그대로 유지합니다.
- 이 형식들에서는 [n], [menu_sita], [0xADB6]를 특별한 지시자로 해석하지 않습니다.
- 인코딩 불가 문자나 NUL 삽입은 오류입니다. 오류 문자를 버리거나 ?로 바꾸지 않습니다.
- 빈 내용은 문자열을 비웁니다(World.Dat 이름은 제외). ID 자체를 지우면 전체 입력 검사가 실패합니다.
- 한글 -> 기존 치환표 -> EUC-JIS-2004 순서로 저장합니다.
