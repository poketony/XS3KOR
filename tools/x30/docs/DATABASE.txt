명령 실행 기준: XS3KOR/tools/x30. 일상 작업 순서는 ../README.txt를 참고하세요.
검증 개수와 초기 번역 상태는 구현 당시의 기록이며 현재 결과와 다를 수 있습니다.

XS3KOR/0.X30/mnu/kr/DBC.bin.KOR.txt를 수정하고 같은 폴더의 Build_database.bat를 실행하면 DBC.bin.new와 DBC2.bin.new가 나옵니다. 검증 후 .new를 제거한 이름으로 X30_UNPACKED/mnu/jp에 직접 적용합니다.

tools/x30 안의 코드와 작업 폴더의 DBC.bin/DBC2.bin/TXT/치환표를 직접 사용합니다. tools/x30/edit에 번역 사본을 두지 않습니다. 게임 내 확인은 아직 하지 않았습니다.
원본 ISO나 외부 ROM 작업 폴더를 실행 중 읽지 않습니다. sources.json의 해시로 작업 폴더의 두 원본 BIN과 치환표를 검사합니다.
TXT는 UTF-8이고, 출력은 한글 -> 치환표의 대응 문자 -> EUC-JIS-2004 순서로 인코딩합니다.
원문 재추출은 Extract_database.batlock을 사용할 때만 .bat로 바꿉니다. 기존 DBC.bin.KOR.txt가 있으면 덮어쓰지 않고 중단합니다. 추출 결과는 일본어 원문이며 이름은 기존 작업 형식과의 호환용입니다. 사용 후 .batlock으로 돌립니다.

편집 형식
- 기존의 0x주소|본문 형식을 유지합니다. 총 3,624행이며 공유 문자열 때문에 같은 주소가 여러 번 나옵니다.
- 같은 주소는 같은 번역으로 맞춰야 합니다. 서로 다르면 마지막 줄로 조용히 덮지 않고 줄 번호를 보여 주며 중단합니다.
- 행을 재정렬해도 주소로 대응시키지만, 주소별 행 개수는 원본과 같아야 합니다. 누락/추가/오타 주소는 중단합니다.
- 내용을 비우면 그 문자열이 실제로 지워집니다. 항목 행 자체를 삭제하는 것과 다릅니다.
- 공백, 문장 부호, 꺾쇠와 문자 그대로인 \n/\r 제어 표기를 자동으로 교정하거나 제거하지 않습니다.
- 인코딩 불가능 문자나 NUL이 있으면 저장 전에 실패합니다. 실패한 빌드의 이전 결과를 적용하지 마세요.
- DBC2의 별도 번역 TXT를 만들거나 수동 주소를 고칠 필요가 없습니다.

두 파일의 대응
- 각 파일에 DBF 항목 453개, 문자열 필드 3,624개가 있습니다. 항목 크기는 208바이트이며 마지막 항목의 끝 패딩은 생략됩니다.
- 문자열 포인터는 각 DBF 항목의 +12, +20, +36, +40, +44, +48, +52, +56 위치입니다.
  숫자와 포인터가 우연히 같은 값이라는 이유로 다른 위치를 수정하지 않습니다.
- DBC와 DBC2의 항목 ID 및 필드 번호를 맞추고, 원문 바이트까지 같을 때 같은 번역을 적용합니다.
- +12는 DBC에서 분류명, DBC2에서 일본어 읽기별 그룹값입니다. 서로 다른 401개 그룹값은 DBC2 원본을 유지합니다.
  이것은 한국어 가나다순 재정렬 기능이 아닙니다. 기존 정렬/검색 구조와 화면 동작은 게임 확인이 필요합니다.
- 다른 필드의 원문이나 항목 ID가 다르면 임의로 연결하지 않고 중단합니다.
- 하나의 원본 주소를 여러 필드가 공유하더라도 각각 다른 결과가 필요한 경우 실제 참조별로 분리할 수 있습니다.
- 짧아지는 문자열은 원래 자리에서 NUL 패딩, 길어지는 문자열은 기존 방식대로 파일 끝에 추가합니다.
  데이터셋 위치/크기 메타데이터는 바꾸지 않습니다. 원래 참조를 따라 7,248개 출력 문자열을 다시 확인합니다.

사용자가 승인한 기존 TXT 수정
- 147행: 149행의 문장으로 통일. '특수 재단 쿠카이 파운데이션 대표 이사'.
- 509행: 507행의 문장으로 통일. '방울 소리와 함께 종종 시온의 앞에 환영으로 나타나는 소녀'.
- 1404행: 인코딩 불가능한 U+2014 두 글자를 일본어 원문과 같은 U+2015 두 글자로 변경.
  '기간 프로그램——즉' -> '기간 프로그램――즉'. 주변 문장과 다른 문장 부호는 바꾸지 않았습니다.
- UTF-8 BOM, CRLF, 3,624행은 유지합니다. 원래 버전은 ../backups/2026-10-23-xs3-existing-work.zip에 보존되어 있습니다.
- 기존 TXT의 같은 주소/다른 번역 사례를 정리하는 것은 승인되었지만, 의미나 문장 선택이 애매하면 다시 확인합니다.
  일반 번역문/문장 부호/도구 코드의 일괄 변경을 승인받았다는 뜻은 아닙니다.

검증과 제한
- python -B build_database.py --check: 저장 없이 두 파일의 빌드 결과를 검증합니다.
- python -X utf8 -B -m unittest discover -s tests -p test_database.py: 원본 전체 왕복, 실제 번역 전체 참조, 공유 주소, 길이 증가/감소,
  포인터와 같은 숫자 보존, 잘못된 입력/원본 해시로 인한 저장 차단, 작업 TXT 직접 사용/누락 감지 등 16개 테스트를 실행합니다.
- 두 파일은 모두 검증한 뒤 파일별 .pending -> 교체 방식으로 저장합니다. 두 파일 전체가 원자적으로 교체되는 것은 아닙니다.
- 저장 도중 디스크 오류/강제 종료가 발생하면 결과가 섞일 수 있습니다. BUILD SUCCEEDED와 종료 코드 0을 확인하세요.
- 출력물을 새 기준 원본으로 쓰지 마세요. original에서 매번 다시 빌드하여 번역 취소와 반복 실행 결과가 일관되도록 합니다.
- 바이트 검증은 게임 로딩/분류 이동/검색/줄 폭/폰트 정상 표시를 보증하지 않습니다.
